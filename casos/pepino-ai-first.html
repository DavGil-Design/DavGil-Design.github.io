Flypass · Design System · 2025—2026

Pepino, el design system de Flypass, ahora también lo entienden los agentes de IA

Cuando el equipo empezó a construir pantallas con Claude Code y Cursor, el design system pasó a ser la fuente de verdad también para las máquinas. Mi trabajo: que lo que diseñamos en Figma llegue al código generado sin perder estilo, comportamiento ni accesibilidad.

Rol
UX Designer · DS & IA
Equipo
Diseño + desarrollo front-end
Herramientas
Figma, Claude Code, MCP, Storybook
Estado
En producción, en expansión

El problema

Pepino ya existía como librería de web components (pp-*) con wrappers para Angular, React y Vue, pero tenía tres fricciones:

  • Figma y código se desalineaban. Mismo componente, distintos nombres, estados o tokens.
  • La IA inventaba UI. Un agente sin contexto genera botones "parecidos" con colores hex sueltos, no componentes reales.
  • El DS era un cuello de botella. Cada pantalla nueva dependía de que alguien conociera la librería de memoria.

Qué hice

1. Componentes interconectados entre Figma y desarrollo

Junto con desarrollo reconstruimos componentes con apoyo de IA, revisando accesibilidad, estados y fidelidad visual contra Figma. Cada componente terminado queda conectado en tres capas: Figma ↔ repositorio ↔ especificación para agentes.

2. Decisiones de diseño documentadas en un contrato: DESIGN.md

Diseñé la estructura de un DESIGN.md sin trabajo duplicado: los tokens vivos se consultan en el código, y el documento cubre lo que el código no puede inferir, como reglas de uso, patrones de composición y anti-patrones.

# DESIGN.md (extracto ilustrativo)
tokens: fuente viva → paquete del DS (no se copian aquí)
patrón: error de red
  usar: pp-alert + acción "Reintentar"
  tipografía: token semántico de título S, cuerpo M
  nunca: modal bloqueante para errores recuperables

3. Un servidor MCP para que los agentes encuentren lo correcto

Con el equipo de desarrollo, el DS se expuso por MCP. Un agente puede pedir qué componente usar, su especificación, el snippet para su framework, el token exacto de un color de Figma o el mapeo de un nombre de Figma a su componente pp-*.

Diseño en Figma→find_component_for→get_component_spec→generate_component_code→UI on-brand

Como el MCP lee la versión instalada del DS, actualizar la librería basta para que los agentes vean los componentes nuevos. No hay que mantener dos fuentes de verdad.

Así, las decisiones de Pepino llegan al ciclo de trabajo de otras personas sin importar la herramienta de IA que usen: Claude, Lovable o Figma Make.

4. pp-ui: prototipos on-brand en minutos

Creé una skill llamada pp-ui, que genera demos y prototipos con los tokens y la gobernanza de Pepino. Producto y negocio validan ideas con UI realista antes de pedir diseño de alta fidelidad.

Resultados

15componentes integrados entre Figma, repo e IA
~56componentes priorizados en backlog de migración
4frameworks soportados desde una sola fuente (web components + Angular, React, Vue)

Además, la primera feature grande diseñada sobre este modelo fue carga eléctrica en la app.

Lo que aprendí

Un design system AI-first no es "documentar más". Es decidir qué vive en el código, qué vive en el documento y qué tiene que entender el agente. El mejor indicador de calidad es que el código generado no necesite que un diseñador lo corrija.
